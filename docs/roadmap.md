# DSH-Memory 后续升级顺序

## 2026-11-14：兼容性优先

本轮修复 Windows 目录同步 `EPERM` 使插件初始化提前退出、备份恢复目标目录冲突、追加失败后回滚不完整、本地语义引擎误把盘符路径当作 URL，以及仅有一条记忆时 IDF 按两条计算导致无标签正文漏召回的问题。文件写入失败仍必须报错；不通过补标签或普遍降低门槛掩盖漏召回。Windows 运行结果和真实宿主验收分别记录在 [verification §81](verification.md#81-windows-持久化与小库召回2026-11-14)。

| 顺序 | 下一项 | 具体收益与完成标准 |
|---|---|---|
| 1 | 安装后的链路诊断 | 将启用、收到用户消息、提炼路由、提炼结果、词法/语义就绪和实际注入分开显示。能定位“未采集”还是“已存但未召回”，诊断导出不含私人原文。 |
| 2 | 离线模型准备 | 明确首次本地模型下载与索引进度，完善可恢复下载和当前宿主网络接入；模型不可用时保留可靠的词法及授权原文召回。不能把空闲状态误报故障。 |
| 3 | 增量向量与 Obsidian 扫描 | 只处理变化的来源与笔记，分别测模型加载、首次索引、缓存重开、首查和未变化同步耗时。既有约 304ms 缓存样本不代表稳定低于 300ms，也不代表完整宿主启动。 |
| 4 | 新装与复杂问答质量 | 用空库、单条无标签、离线、新项目、多问、否定、历史与当前混问验证真实证据覆盖和回答；项目隔离与遗忘继续作为边界，不为命中率放宽。 |

本轮没有重写存储或更换数据库。真实 Windows Node 测试不等于已验收每台 Windows DSH 的界面、宿主事件和用户网络环境。

## 2026-11-10：按当前代码重新盘点

当前已经有多问拆分与最终注入覆盖统计、本地语义检索、授权原文分段索引、持久化提炼队列及预算续跑。它们不再列为“尚未开发”。当前实现与历史验证见 [verification](verification.md#76-p0p1-完整覆盖本地语义与原文分段2026-11-07)。

本轮把笔记合并到记忆入口，统一下拉控件，并为 Obsidian 增加按项目隔离、按用途汇集的阅读页及主题索引。[Demo](demo/obsidian-vault/README.md) 展示进一步的连贯笔记体验；其中手写的场景、工作流与日记不冒充当前自动生成能力。阅读页只整理已有原话，不自动发起模型调用，也不替代 JSONL 与 Markdown 源文件。

本轮已实现有限关系追查、有证据的主题归并、来源批量校验与同步解析复用。独立合成检查已通过，安装与原生验收另记于 [verification](verification.md#80-关联召回主题归并与混合容量2026-11-10)。下表保留各方向目标；自动长篇摘要、全量向量化评估以及稳定低于 300ms 的混合库重开仍未完成：

| 顺序 | 升级 | 具体解决什么 | 验收标准 |
|---|---|---|---|
| 1 | 有依据的关系追查 | “负责人是谁、他请假谁接手、为什么改”可能需要连接多条证据。沿对象、关系和有效时间做有限步补查，复用已完成回执；不恢复关系图页面。 | 多跳、同名项目、历史与当前混问的每项答案都能指回原句；越权与遗忘内容不进入候选和注入；用量不重复。 |
| 2 | 主题笔记质量 | 当前阅读页已经汇集同主题原话，但主题名过细、同义名和未分类内容仍影响阅读。先提供有证据的主题归并，再考虑带逐段引用的自动摘要。 | 不只换标题；原句、否定、条件、决定原因完整保留。摘要与原文分开，来源改动和遗忘后失效；手写补充和冲突副本保留。 |
| 3 | 混合容量与增量维护 | 用记忆、长原文、完整笔记一起衡量容量，减少未变文件扫描和重复构建；阅读页也只随来源变化更新。 | 分别报告首次构建、缓存重开、模型加载、首查/稳定态 p95、内存和同步耗时。50k 缓存重开 ≤300ms 仅为指定环境目标，不能代替全宿主启动指标。 |
| 4 | 独立质量评估 | 将“检索到了”和“最终答对了”分开；当前自动化测试不能保证任意聊天都准确。 | 新增开发集之外的改写、多问、时序、原因、跨项目、遗忘问题；报告候选/注入覆盖、真实答案、错误引用、延迟和花费。 |

基本边界继续保持：记忆数据可读、原文有授权才召回、项目边界与遗忘优先、调用结果未知不重发、Obsidian 双向编辑不静默丢内容。当前无需为这些目标更换数据库或重写整个系统。

# 记忆插件路线图（v0.2 → v1.0）

> 现状（v0.1，已完成）：自动捕获 + 上下文注入 + 设置页面板（B 卡片分区、活动热力图、类型页签、分页）+ JSONL 权威存储 + 进程内 BM25；

> 原则：本地优先、零运行时依赖、明文可读、删除可传播。

## 北极星

> 聊得越久，它越懂我；换一个会话，它还记得；用得越多，记忆越准而不是越乱。

衡量方式（可自动化）：
1. **召回命中率**：构造 30 条「该被想起」的测试对话，注入块命中 ≥ 80%。
2. **准确率**：注入记忆中被用户标记「不相关」的比例 < 10%。
3. **精度**：人工抽检 50 条，重复/矛盾记录 < 5%。
4. **性能**：5000 条规模召回 p95 < 50ms（当前 8.8ms）。
5. **可靠性**：重启、崩溃、损坏行、LLM 失败四类场景不丢数据。

## 风险与取舍

- **向量检索**：暂不做。JSONL + BM25 已满足本地规模；引入 embedding 会破坏零依赖与可重建性。
- **知识图谱**：暂不做。记忆条目之间的关联先用「同主题合并 + supersede」表达。
- **自动衰减**：episode 90 天保留先作为配置项；真正的衰减曲线等反馈数据够了再做。
- **多设备同步**：不在路线图内，本地优先是产品边界。
- **Laya 决策模型**：laya-mcp 官方说明基础 checkpoint 在 typed decision 上接近随机（0.362 vs 多数类 0.461），且选项 >20 准确率下降；只能作为需要自校准的可选项，不能默认启用。
- **与其它记忆插件共存**：MSE 的 `[[mse-learned]]` 与我们的 `<memory-context>` 数据不共享、可共存（token 增加）；与 TDAI / dsh-self-improved 的捕获+注入重叠，建议只保留一个注入器（详见调研文档第 4 节）。

## 团队评审结论（2026-11-02，三位只读评审）

三位子代理分别从「记忆质量 / 产品运维 / 架构可靠性」独立评审，未改文件。共识优先级：

### P0 · 必须先做（数据安全 + 有尺子）
1. **写入并发与崩溃安全**（架构）：当前无进程锁、无 fsync；同一 revision 并发写入会被加载器静默丢弃；压缩用旧快照重写可能覆盖并发追加。→ 排他锁 + 心跳 + 锁内重读 + fsync + 备份。✅ 已实现（跨进程锁、fsync、压缩锁内重读、revision 冲突递增）
2. **坏行 / 版本 / 备份**（架构 + 产品）：坏行只计数、压缩即永久丢失；打开存储时版本号被无条件写回 1；没有导出/备份。→ 坏行隔离告警、版本迁移、导出/导入 + 每日备份。✅ 后端已实现（坏行隔离、schema v2 迁移、export/import/backup）；面板按钮待接
3. **评测集**（质量）：93 个测试只验机制，没有标注集；无法回答“记得准不准”。→ 30–50 条 case（应召回 id / 应抽取条目），算 hit@5、precision、重复/矛盾率、抽取 F1，进 CI。✅ 已实现 30 条召回 case（hit@5=1.000，MRR=0.983）

### P1 · 记忆质量（有评测集后做）
4. **合并与冲突**（质量）：`Node22→24` 这类值变化被 Jaccard 0.905 当重复、保留旧值；→ 同 topic/实体先配对，值/否定差异走 SUPERSEDE；0.7–0.9 灰区才调一次 LLM。✅ 值/否定冲突已走 SUPERSEDE（LLM 灰区仍待做）
5. **召回门控**（质量）：当前按 top 归一，单条弱命中也能过 0.15；CJK 单字任意相同即命中；→ 绝对 BM25 下限 + 至少一个 bigram，单字只做 tiebreak。✅ 已实现 bigram/长词门控（绝对分数下限待评测校准）
6. **画像质量**（质量）：相似度 0.42 会把「深色/浅色主题」合成一条；同 topic 不比相似度直接合并；→ 同 topic 也要相似度 + 反义检测，置信度按证据累积。
7. **续问查询**（质量）：只取最后一条 user 消息，「继续/好」召回为空；→ 近 2 条 user 消息 + topic 软加分。✅ 短续问已改用上一条用户消息（topic 软加分待做）

### P1 · 产品与运维
8. **设置可写**（产品）：捕获/注入开关、预算、保留天数真正落配置；→ 面板设置卡 + 配置读写接口。
9. **批量与回收站、详情与版本历史、主题治理**（产品）：批量操作、软删除回收站、revision 抽屉、46/140 主题覆盖率的补全与筛选。

### P2
10. 索引持久化与懒加载（50k 启动 1.9s / 181MB / 查询 112ms）、抽取持久任务与重试幂等、压缩策略与可观测、搜索高亮、共存提示。

**建议启动顺序**：P0-1 写安全 → P0-2 坏行/版本/备份 → P0-3 评测集 → P1-4 合并冲突 → P1-5/6/7。
