# 记忆插件路线图（v0.2 → v1.0）

> 现状（v0.1，已完成）：自动捕获 + 上下文注入 + 设置页面板（B 卡片分区、活动热力图、类型页签、分页）+ JSONL 权威存储 + 进程内 BM25；
> 86/86 单测；真实 73 条记忆；浏览器端 stats/list/activity RPC 已验证；重启/卸载循环已验证。
> 原则：本地优先、零运行时依赖、明文可读、删除可传播。

## 北极星

> 聊得越久，它越懂我；换一个会话，它还记得；用得越多，记忆越准而不是越乱。

衡量方式（可自动化）：
1. **召回命中率**：构造 30 条「该被想起」的测试对话，注入块命中 ≥ 80%。
2. **准确率**：注入记忆中被用户标记「不相关」的比例 < 10%。
3. **精度**：人工抽检 50 条，重复/矛盾记录 < 5%。
4. **性能**：5000 条规模召回 p95 < 50ms（当前 8.8ms）。
5. **可靠性**：重启、崩溃、损坏行、LLM 失败四类场景不丢数据。

## 主线与优先级

| 优先级 | 主线 | 要做的事 | 验收 |
|---|---|---|---|
| P0 | 设置可写 | 面板的捕获/注入开关、预算、保留天数改为真实配置写入（Host Config + RPC），而不是只读展示 | 改开关后重启仍生效；注入块随之出现/消失 |
| P0 | 数据可搬运 | 导出（JSONL/JSON 打包）、导入合并、清空项目、备份到指定目录 | 导出再导入后条数/内容/revision 一致 |
| P0 | 抽取质量 | 抽取 prompt 加 few-shot 与反例；忽略寒暄/代码块；中文实体保真；失败重试一次 | 抽检 50 条，重复/无关 < 10% |
| P1 | 反馈闭环 | 面板里的编辑/删除/批准作为反馈：提升/降低 importance、同类偏好合并、候选自动收敛 | 编辑后同主题记录减少，importance 有变化 |
| P1 | 召回质量 | 打分加入 recency/importance/命中次数；preference 优先占预算；召回结果按主题去重 | 注入块前 3 条相关性抽检 ≥ 80% |
| P1 | 长对话兜底 | 中断 turn 的缓冲 flush、压缩事件补抽取、超长对话分块上限可配 | 中断会话后仍能捕获当前轮内容 |
| P2 | 批量与详情 | 多选批量归档/删除、按时间/置信度排序、revision 历史查看 | 面板可完成批量操作且刷新一致 |
| P2 | 分发 | npm 包 + README 安装/卸载、CHANGELOG、CI（node --test）、与 TDAI 共存说明 | 新机器按文档 5 分钟内装上并看到面板 |

## 里程碑

### v0.2（建议下一迭代，1–2 周）
1. 设置可写：`capture.enabled`、`inject.enabled`、`inject.maxTokens`、`retention.episodeDays`。
2. 导出/导入：面板按钮 + 文件选择，导出 `memories.jsonl` 与 meta；导入去重合并。
3. 抽取质量：prompt few-shot + 反例 + 失败重试；抽检脚本 `scripts/eval-extraction.mjs`。
4. 回归：`node --test` 全绿，面板手动验收清单过一遍。

### v0.3（质量迭代：越用越懂）
> 参考 [docs/memory-plugins-survey.md](memory-plugins-survey.md)：jev-agent-memory 的证据化 profile、dsh-self-improved 的 L2/L3、ironcurtain 的三层去重。
1. **Profile 层（L3）**：从 preference/decision 聚合 5–10 条用户画像，每条带 confidence、last_seen、evidence（原文 + 日期 + 记录 id）。✅ 已实现（仅偏好，上限 10 条，面板画像卡 + 注入）
2. **证据校验**：画像引用必须能在记忆条目中找到；无证据不进画像；情绪不进画像。✅ 已实现（evidence 直接取自记录）
3. **时间衰减**：episodic 90 天、profile 60 天半衰期，只降权不删除；`last_seen` 随新证据刷新。✅ 已实现（召回按类型半衰期，画像 60 天）
4. **L2 场景分组**：记忆加 `topic`，召回先按主题过滤再打分。✅ 字段 + 抽取 + 索引已实现（按主题的过滤分面待做）
5. **三层去重**：精确 Jaccard → 灰区 LLM 判定 → 矛盾标记 supersede。🟡 第一层精确 + 灰区 0.85 规则已实现；LLM 边界判定待做
6. 反馈闭环（编辑/删除/批准 → importance/confidence 调整）。
7. 召回打分与预算策略；构造 30 条召回测试集并跑分。

### v0.4（规模化 + 可选决策模型路由）
1. **决策模型路由（可选）**：`router` 接口（输入消息 + 候选记忆 + 预算 → picked ids + confidence），默认本地 BM25；可选 Jev HTTP（需 key，默认关闭）或 Laya sidecar（本地，需先校准）；失败自动回落。
2. 决策 trace（`router.jsonl`）可审计；用 30 条召回测试集对比 BM25 / Jev / Laya 再决定是否默认开启。
3. 索引持久化（> 5 万条时内存索引启动慢的问题）。
4. 批量操作与 revision 历史；时间范围筛选。
5. 导出格式增加 Markdown（人读）与 CSV（分析）。

### v1.0（可分发）
1. npm 发布、CHANGELOG、CI、安装文档。
2. 与 `@missher/dsh-memory-tdai` 共存策略（检测重复注入并提示禁用其一）。
3. 性能与可靠性指标固化进 CI。

## 风险与取舍

- **向量检索**：暂不做。JSONL + BM25 已满足本地规模；引入 embedding 会破坏零依赖与可重建性。
- **知识图谱**：暂不做。记忆条目之间的关联先用「同主题合并 + supersede」表达。
- **自动衰减**：episode 90 天保留先作为配置项；真正的衰减曲线等反馈数据够了再做。
- **多设备同步**：不在路线图内，本地优先是产品边界。
- **Laya 决策模型**：laya-mcp 官方说明基础 checkpoint 在 typed decision 上接近随机（0.362 vs 多数类 0.461），且选项 >20 准确率下降；只能作为需要自校准的可选项，不能默认启用。
- **与其它记忆插件共存**：MSE 的 `[[mse-learned]]` 与我们的 `<memory-context>` 数据不共享、可共存（token 增加）；与 TDAI / dsh-self-improved 的捕获+注入重叠，建议只保留一个注入器（详见调研文档第 4 节）。

## 团队评审结论（2026-11-02，三位只读评审）

三位子代理分别从「记忆质量 / 产品运维 / 架构可靠性」独立评审，未改文件。共识优先级：

### P0 · 必须先做（数据安全 + 有尺子）
1. **写入并发与崩溃安全**（架构）：当前无进程锁、无 fsync；同一 revision 并发写入会被加载器静默丢弃；压缩用旧快照重写可能覆盖并发追加。→ 排他锁 + 心跳 + 锁内重读 + fsync + 备份。✅ 已实现（跨进程锁、fsync、压缩锁内重读、revision 冲突递增）
2. **坏行 / 版本 / 备份**（架构 + 产品）：坏行只计数、压缩即永久丢失；打开存储时版本号被无条件写回 1；没有导出/备份。→ 坏行隔离告警、版本迁移、导出/导入 + 每日备份。✅ 后端已实现（坏行隔离、schema v2 迁移、export/import/backup）；面板按钮待接
3. **评测集**（质量）：93 个测试只验机制，没有标注集；无法回答“记得准不准”。→ 30–50 条 case（应召回 id / 应抽取条目），算 hit@5、precision、重复/矛盾率、抽取 F1，进 CI。✅ 已实现 30 条召回 case（hit@5=1.000，MRR=0.983）

### P1 · 记忆质量（有评测集后做）
4. **合并与冲突**（质量）：`Node22→24` 这类值变化被 Jaccard 0.905 当重复、保留旧值；→ 同 topic/实体先配对，值/否定差异走 SUPERSEDE；0.7–0.9 灰区才调一次 LLM。✅ 值/否定冲突已走 SUPERSEDE（LLM 灰区仍待做）
5. **召回门控**（质量）：当前按 top 归一，单条弱命中也能过 0.15；CJK 单字任意相同即命中；→ 绝对 BM25 下限 + 至少一个 bigram，单字只做 tiebreak。✅ 已实现 bigram/长词门控（绝对分数下限待评测校准）
6. **画像质量**（质量）：相似度 0.42 会把「深色/浅色主题」合成一条；同 topic 不比相似度直接合并；→ 同 topic 也要相似度 + 反义检测，置信度按证据累积。
7. **续问查询**（质量）：只取最后一条 user 消息，「继续/好」召回为空；→ 近 2 条 user 消息 + topic 软加分。✅ 短续问已改用上一条用户消息（topic 软加分待做）

### P1 · 产品与运维
8. **设置可写**（产品）：捕获/注入开关、预算、保留天数真正落配置；→ 面板设置卡 + 配置读写接口。
9. **批量与回收站、详情与版本历史、主题治理**（产品）：批量操作、软删除回收站、revision 抽屉、46/140 主题覆盖率的补全与筛选。

### P2
10. 索引持久化与懒加载（50k 启动 1.9s / 181MB / 查询 112ms）、抽取持久任务与重试幂等、压缩策略与可观测、搜索高亮、共存提示。

**建议启动顺序**：P0-1 写安全 → P0-2 坏行/版本/备份 → P0-3 评测集 → P1-4 合并冲突 → P1-5/6/7。  
**只做一件**：先做 P0-1（数据安全），或先做 P0-3（评测集）看你要“稳”还是“准”。


### 反馈闭环（新增）
- 面板批准 / 编辑 / 固定会写回 confidence 与 importance；画像按证据重算，用户行为开始影响后续召回。


### 自维护（v0.5 完成）
- ✅ 自动归档低价值旧 episode、每日备份、旧备份清理、维护报告。
- ✅ 设置可写：捕获/注入开关、注入预算、片段保留、自维护开关（settings.json + live 生效）。
- ✅ 面板导出/导入/备份入口（JSON 导出、按 revision 去重导入、立即备份）。


## 升级方案（v0.6 → v1.0，2026-11-02）

完整方案见 [docs/upgrade-plan.md](upgrade-plan.md)。摘要：

- **v0.6 记得准**：绝对分数门控 + 0.7–0.9 灰区判定、最近 2 条用户消息续问、画像同主题/反义检测、多相关项评测（precision@5 ≥0.40）。
- **v0.7 好管理**：回收站、批量操作、详情与版本历史、主题治理（先 demo 再接入）。
- **v0.8 扛得住**：索引持久化/懒加载、抽取持久任务、压缩可观测、20k/50k 基准（p95 ≤50ms）。
- **v1.0 可交付**：回归 + 迁移演练 + 文档对齐 + 版本与变更日志。
- 顺序理由：先准（召回/画像）→ 再好管（生命周期）→ 再扛规模；不引入向量库，UI 先 demo。
