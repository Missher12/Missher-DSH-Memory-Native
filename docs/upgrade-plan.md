# DSH 记忆插件 · 升级方案（v0.6 → v1.0）

> 2026-11-02 制定。当前已完成 v0.5「自掌控」：自维护、设置可写、导出/导入/备份、设置区重造并接入真实面板。
> 原则：**先准、再好管、再扛得住**；每个里程碑不降低现有测试与评测基线；UI 先 demo 后接入；不引入向量库/图数据库/新的运行时依赖。

## 0. 现状基线

| 项 | 当前值 | 证据 |
| --- | --- | --- |
| 真实记录 | 182 条（项目 + 全局） | 面板自检 `total=182` |
| 单元测试 | 112/112 | `node --test tests/*.test.js` |
| 召回评测 | hit@5 1.000 · MRR 0.983 · precision@5 0.225 | `npm run eval`（30 case，单相关项） |
| 检索性能 | 5,000 条：build 109ms · 中位 4.05ms · p95 8.31ms | `npm run bench` |
| 已有能力 | 写安全/坏行隔离/schema v2/导出导入备份/冲突 SUPERSEDE/反馈写回/召回门控/续问/自维护/设置可写 | 文档与测试 |

已知短板：绝对分数门控缺失、画像同主题未做反义检测、0.7–0.9 灰区无二次判定、无回收站/批量/详情版本、topic 覆盖约 1/3、启动全量重建索引、抽取任务不落盘。

## 1. v0.6「记得准」（P0，约 1–2 周）

目标：把「不准」压下去，让注入的每一条都值得出现。

1. **召回门控 v2**
   - 绝对 BM25 下限（按语料规模标定）+ 单字命中只做 tiebreak，不单独触发注入。
   - 0.7–0.9 灰区：有可用模型时做一次轻量相关性判定；不可用/失败时降级为「不注入」并记录候选，不阻塞主流程。
   - 验收：弱查询（你好/好的/今天天气）注入 0；评测 hit@5 不下降。
2. **续问与话题**
   - 查询取最近 2 条 user 消息；短续问沿用当前策略并补充上一条的 topic。
   - topic 软加分（有 topic 记录 +0.05~0.1），不改变排序方向。
   - 验收：续问用例命中率 ≥0.9；主题相关查询 top5 含 topic 记录比例提升。
3. **画像质量**
   - 同 topic 也要相似度判定；否定/反义（如「喜欢 A」vs「不喜欢 A」）不再聚成同一条。
   - 证据累积：同主题多条一致证据提升 confidence，冲突证据走 SUPERSEDE。
   - 验收：画像条目数不虚增；反义用例不合并；冲突用例 correct supersede。
4. **评测升级**
   - 每个 case 标注 2–3 条相关项，新增「不相关注入率」指标。
   - 目标：hit@5 ≥0.95、MRR ≥0.95、precision@5 ≥0.40、不相关注入 ≤10%。
   - 测试 ≥125。

## 2. v0.7「好管理」（P1，约 1–2 周）

1. **回收站**：软删除列表、恢复、彻底删除（二次确认）；删除操作全部走 tombstone。
2. **批量操作**：多选归档/删除/加标签；失败时回滚并提示。
3. **详情 + 版本历史**：完整字段、revision 列表、diff、恢复旧版本（写新 revision，不破坏历史）。
4. **主题治理**：自动 topic、无主题筛选、近似主题合并建议。
- 验收：所有写操作幂等；回收站/恢复往返测试；面板 735/520/430 无溢出；先出 demo 再接入。

## 3. v0.8「扛得住」（P2，约 1–2 周）

1. **索引持久化/懒加载**：启动只读 meta + 增量索引文件；损坏时回退全量重建并记录。
2. **抽取持久任务**：任务落盘、重试幂等、失败状态在面板可见。
3. **压缩可观测**：记录前/后行数、字节、耗时，写入 `maintenance.json` 扩展字段。
4. **规模基准**：20k / 50k 合成数据 build、查询、写入基准；50k p95 查询 ≤50ms，启动 ≤300ms。
- 验收：崩溃/断电模拟不丢已确认记录；bench 脚本纳入 `npm run bench`。

## 4. v1.0「可交付」（约 1 周）

- 全量回归 + 迁移演练（schema v2 → 未来版本、导出/导入跨版本）。
- 文档对齐：README / design-requirements / verification / upgrade-plan。
- 打包与版本号、变更日志；不自动推送 Git。
- 验收：112+ 测试、eval 达标、bench 达标、手动验收清单全过。

## 5. 排序理由

- 「越用越懂」的核心是**召回准、画像准**，功能堆叠不解决信任问题，所以 v0.6 先做质量。
- 数据可恢复、可审计是长期使用的前提，v0.7 做生命周期。
- 当前 182 条、5k 合成数据 p95 8.3ms，规模不是瓶颈；v0.8 做防御性优化与可观测。

## 6. 风险与对策

| 风险 | 对策 |
| --- | --- |
| LLM 灰区判定依赖外部调用 | 超时/失败降级为不注入 + 记录候选；不阻塞 turn |
| 索引持久化格式升级 | 版本号 + 迁移 + 失败回退全量重建 + 回滚开关 |
| 批量/回收站误操作 | 软删除 + 二次确认 + 批量失败回滚 |
| 评测集过拟合 | 保留 held-out case；每次改召回参数先跑全量评测 |

## 8. 明确不做

- 向量库/图数据库/云同步/多用户协作。
- 自动改写用户原话或未经确认的外部写入。
- 自动推送 Git、自动发布。
