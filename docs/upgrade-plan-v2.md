> 2026-11-03 制定。上一版（v0.6 质量 / v0.7 管理 / Obsidian DLC / 知识图谱 / 八标签）已完成。

**主要短板**
1. 知识库还没有闭环：知识笔记不能在面板编辑，Obsidian 只同步记忆、不同步 `knowledge/*.md`，vault 里的笔记也不进图谱。
2. 规模：50k 查询 p95 133ms、内存 298MB，启动 build ≈1s，超出 v0.8 目标（p95 ≤50ms、启动 ≤300ms）。
3. 抽取任务只在内存里，进程崩溃会丢当前 turn 的抽取；压缩/维护可观测性有限。
4. 体验尾部：图谱无时间过滤/布局保存；430 宽度标签换行；画像 trait 只能看不能改/合并。

## 0.5 Token 预算 v2（与 v0.10 并行，优先）

已落地（v0.6.0）：注入 526.6→273.9 token/步（−48%）、抽取固定开销 579→360、GUIDANCE 125→66、单轮典型 4113→2392（−42%）；注入预算 360、短续问 220、existing 6×80、transcript 16k。

已落地（v0.6.x Token v2 第一批）：注入预算按命中数自适应 200/256/352（续问 220）；capture 记录 `{promptTokens,transcriptChars,chunks,calls,items,applied}`，`stats.lastExtraction` 可见；设置摘要显示抽取 token。

已落地（v0.6.x Token v2 第二批）：抽取输出收紧为每次 ≤4 条、每条 ≤120 字、`maxOutputTokens` 600→400；输出被截断时从已写完对象中恢复（`salvageMemories`），capture 接受 `finish=length` 并记录 `truncated`；`usage.jsonl` 记录每次注入/抽取，`stats.usage` 返回补零的 7 天序列、总量、平均注入与超预算次数，「捕获与注入」tab 显示分组柱状图与图例。

剩余：
1. **增量抽取边界**：回合内 20000 字符触发、最多 2 次已实现；补块边界遥测与超长回合的丢弃计数。
2. **低价值跳过**：纯操作/无用户文本/灰区查询不注入（已有），profile-only 不单独注入（已有）。
3. **提示缓存（Host 层）**：固定 RULES/GUIDANCE 前缀尽量稳定，配合 Provider prompt caching；插件只负责前缀稳定。
4. **真实会话采样**：用 `usage.jsonl` 连续 7 天数据核对 p50/p95，而不是只看评测夹具。
- 验收：真实会话 p50 单轮 ≤1800 token、注入 p95 ≤360、抽取 p50 ≤800；eval hit@5 ≥0.95。

## 1. v0.10「知识库闭环」（P0，约 1–2 周）

目标：让「记忆 → 提升 → 长期知识 → Obsidian」真正双向可用。

1. **知识笔记编辑**（已完成 2026-11-04）
   - 知识库 tab 点笔记打开编辑器：标题、正文、topic、tags、`[[链接]]`；保存写回 `knowledge/<id>.md`。
   - 冲突：`expectedMtimeMs` 不匹配时返回 conflict，面板提示重新加载，不静默覆盖；frontmatter 未知字段原样保留。
2. **Obsidian 双向同步知识**（已完成 2026-11-04）
   - 导出：`knowledge/*.md` 同步到 `<vault>/<folder>/knowledge/`，内容不变，相同文件跳过。
   - 导入：vault 中带 `dsh_knowledge: true` 的笔记按文件名进入知识库；同名且内容不同报 conflict，不覆盖本地编辑。
3. **图谱接入 vault**（已完成 2026-11-04）
   - 图谱节点增加 `vault` 类型（青绿色）；本地知识笔记（蓝色）与 vault 笔记分别着色，含图例。
   - 按正文 `[[wiki link]]` 连到已有主题 hub；与本地同名笔记去重，避免双份节点。
4. **图谱体验**
   - 时间过滤（最近 7/30/90 天）；双击主题展开/收起；布局可保存。
5. **画像可编辑**
   - trait 合并/拆分/忽略；合并后保留证据链。
- 验收：知识笔记可编辑并落盘；vault 笔记可导入并出现在图谱；`__errors=[]`；735/520/430 无溢出；测试 ≥160。

## 7. Codex 评审与优先级建议（2026-11-04）

本节是对现有规划和当前源码的评审，不代表功能已实现或通过真实宿主验收。保留本地优先、JSONL 权威记录、可重建索引和现有编辑/同步成果；目标集中在“记得住、记得多、记得精”，不恢复人格/灵魂功能，也不扩展 MSE、Context 的职责。

### 已确认的缺口

- **采集完整性优先于界面扩展。** `host/capture.js:177` 将单条消息截到 4000 字符，缓冲超限会移除旧消息；单批抽取只取前三段，预算耗尽会跳过剩余段。当前队列是进程内 Promise，turn/end 删除缓冲后才调度，不能据此保证重启后继续处理。仅统计丢弃量不能解决来源丢失。
- **事实替换存在失败窗口。** `host/capture.js:418` 的 SUPERSEDE 路径先使旧记录失效，再校验、写入新记录；新项被拒绝或后续写入失败可能留下没有有效替代项的状态。这是源码可见风险，本次未做故障复现。
- **自动抽取的证据定位不足。** 当前新增记录只传入 sessionId，无法直接定位具体原话；UPDATE 和近重复合并也需要保留新增证据。模型评分、重复次数不能替代来源证据。
- **质量指标覆盖有限。** `scripts/eval-recall.mjs` 使用 26 条固定记录、30 道固定检索题；hit@5 只要求命中任一相关项，不能证明完整召回或回答正确。当前 precisionAt5 实际除以返回条数，应明确标为“最多 5 条结果的精确率”或调整计算；脚本失败阈值仍是 hit@5 <0.8，与规划目标 ≥0.95 不一致。
- **省 token 需要质量约束。** 当前每次最多 4 条、每条 120 字、输出上限 400 token；恢复截断 JSON 的完整对象只能保住部分结果。usage 中抽取 tokens 来自估算的 promptTokens，不能作为实际总用量或费用。不能把更少提炼、漏掉条件当作优化成果。

### 建议调整实施顺序

| 优先级 | 工作 | 用户得到的结果 |
| --- | --- | --- |
| P0 | 将原 v0.11 的持久任务前移：保存允许采集的完整来源或可验证、可持续读取的宿主来源定位，记录分段进度，预算不足保留待处理状态；安全恢复和写入幂等 | 长消息末尾、重启前的待处理内容仍能记住；结果未知的付费请求不盲目重发 |
| P0 | 证据与事实更新：关联具体消息/片段、来源角色和时间；区分用户确认、助手推测和引用资料；保证替换失败不丢旧有效项 | 回答能解释“从哪里记得”，修正后用新事实，问过去时仍能找到旧事实 |
| P0 | 明确共享与遗忘语义：同项目跨会话共享，跨项目按显式 scope；检查删除对索引、派生画像、知识笔记及导入/同步的影响 | 不串项目，不把推测变成用户偏好，删除内容不会被后台自动恢复；用户明确重新导入另行处理 |
| P1 | 先建立独立评测，再调召回：覆盖换种说法、否定、时间、同名实体、多会话组合、无答案；同时检查实际注入与最终回答 | 找到所有必要证据，并在证据不足时承认不知道 |
| P1 | 用倒排候选、增量索引及按需读取实现规模目标；基于难例决定是否需要额外语义能力，当前不引入向量/图数据库 | 记忆量增长后仍快，且性能优化不降低有效召回 |
| P2 | 继续图谱交互等扩展；基础页面先保证搜索、来源、修改、遗忘和失败处理清楚，区分总量/本页/待处理数量 | 日常不用理解内部机制，也能查明为什么记住、没记住或没召回 |

“完整来源 → 带证据、可修正的事实 → 按问题选取必要内容”是三个逻辑职责，可沿用现有文件与模块逐步补齐，不需要先推翻重写。原文负责保真，事实负责检索，注入负责控制上下文；摘要不应成为唯一证据。提炼沿用当前宿主的模型路由。

### 验收应衡量能力，而不是测试数量

- 故障与边界用例：长消息首中尾、超过三段、预算耗尽、重启、重复事件、替换写入失败；分别核对已接收来源、处理进度和最终记忆，不能用队列清零代替完成。
- 来源与更新用例：新增事实能追溯原文；助手猜测不升级为用户事实；“以前 A、现在 B”与“现在改回 A”正确；未经新授权的后台流程不复活已遗忘内容。
- 端到端用例：在真实宿主新会话中完成采集、提炼、另一个会话的 pre-step 注入和回答核对；明确共享范围，同时保留不该召回的负例。
- 质量与成本一起报告：独立留出集的必要证据召回、回答正确率、错误注入、无答案拒答，以及耗时和总 token；估算值与 provider 返回用量分开。对比无记忆、当前实现，模型和预算保持可比。固定 30 题仍可作为回归测试，不能单独支持“世界最好”的结论。
- 现有 50k 性能目标可保留，但记录硬件、数据分布及索引是否包含在计时内，并验证优化后的相关难例。测试总数只作记录，不作为质量门槛。

参考：采用 [LongMemEval](https://arxiv.org/abs/2410.10813) 对信息提取、多会话推理、时间推理、知识更新及无答案拒答的能力划分；借鉴 [Graphiti](https://github.com/getzep/graphiti) 的来源追溯和事实有效时间设计。这里借鉴评测与数据语义，不引入其服务或数据库依赖。
