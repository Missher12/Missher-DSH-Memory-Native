# 本地 Memory 可靠性升级设计

用户已选择：把当前本地 DSH 插件做到企业级质量。继续当前 JavaScript/JSONL/Cordis/Typert 架构，由 Codex 在当前会话执行。质量以实际行为验收，不以版本名或竞品标签证明。

## 目标与边界

- 保存操作失败不破坏已提交数据；设置损坏不能静默开启捕获、注入或同步。
- 完整备份保存记忆修订、删除标记、来源、提炼/调用账本、知识笔记和配置；能恢复到新的空目录并核对内容。普通 JSON 导出仍是迁移当前记录，二者名称明确。
- 导入在写入前验证格式、版本、记录和范围；无效输入不写入一部分，不把普通导入当作显式恢复已遗忘内容。
- 本地安全边界是当前 OS 用户与 DSH profile；同 profile 内的全局与项目规则不变。核对真实宿主可用身份，避免多个 profile 隐式共用默认目录，不移动或丢弃当前已安装数据。
- 活动页能看懂降级原因、备份失败、坏行等状态。诊断输出默认不含记忆正文、原始路径、密钥或会话内容。
- 保留已有真实问答和 50k 验收证据。只对修改影响的路径补充有效检查；最终安装、原生运行和恢复行为实际验证。

不引入团队账号/服务器、外部分析服务、新数据库或人格，不修改 MSE/Context，不推送发布。插件不能对同一 OS 用户权限下的恶意程序提供强租户隔离，也不据此宣称合规认证。

## 路线

用户选择保留本地插件并提升质量。增建多人云平台会改变权限、部署和成本范围，不在本轮；推翻 JSONL/现有索引会丢掉刚完成的验证且没有当前必要性。保留现有架构，针对已证明缺口加强持久化、边界与恢复。

## 完成依据

1. 设置原子提交；损坏有明确错误且不回退开启默认功能；写失败保留旧文件，恢复有可用入口。
2. 活进程的写锁不能因超过 30 秒被夺走，死进程锁可恢复；短写、磁盘错误和并发冲突不损坏权威文件。
3. 完整备份原子发布且不覆盖同毫秒备份；坏备份和符号链接不能误导恢复；恢复仅写新的空目标，校验完整性，未知付费请求仍保持未知。失败备份不触发删除有效旧备份。
4. 非法导入全量拒绝，schema 向前版本拒绝，正常导出迁移可用；删除语义不被普通导入绕过。
5. 可验证的 profile 边界与原生健康/脱敏诊断；当前用户数据及配置保留。
6. 相关检查通过，真实宿主安装并核对运行状态；公开记录区分测试范围、真实运行和未验证条件。
